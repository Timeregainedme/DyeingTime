## 1. 目录

```text
docs/test-scripts/
├── A-室内双人对话-template.md/.docx
├── B-都市多场景-template.md/.docx
├── C-单人悬疑-template.md/.docx
├── README.md
└── fixtures/
    ├── A-室内双人对话.md
    ├── B-都市多场景.md
    └── C-单人悬疑.md
```

## 2. 空白模板

模板用于让用户填写真实项目，不是完整剧情：

- A：两名角色、固定室内场景、对白、情绪、简单动作和镜头切换。
- B：三个以上地点、多角色、时间变化、场景切换、关键道具和服装变化。
- C：单一主角、少对白、内心独白/画外音、特写、道具、环境变化和悬念。

Markdown 与 DOCX 保持同一逻辑结构；请复制模板后再填写。

## 3. Fixtures

`fixtures/` 是非空短剧本，用于自动化解析、分镜和纵向 Mock 验收。它们不是模型泛化能力测试，也不应直接用于真实供应商付费测试。

## 4. 全链路 Mock 验收

在 `backend/` 目录执行：

```bash
uv run python scripts/v2_full_acceptance.py
```

脚本覆盖：

- 项目、章节、剧本版本和 Mock 解析状态
- 角色身份、场景、镜头和 P5 资产版本
- H3 参考绑定、`@` 引用、输入快照
- 12 镜 Mock 批量、候选审核、8 镜采纳
- 4 镜选择式 MP4 ZIP 预检查与下载
- 采纳版本切换后的新 ZIP 与旧文件保留
- 额度状态

脚本不调用真实供应商，不消耗测试额度。

## 5. 真实供应商测试

真实调用必须先单独提交验证计划并等待批准。不要因为累计额度未用完就自动执行。
